Flare is one maintainer and a short list of people who have shipped code
into it. The list is short on purpose: it is read off GitHub rather than
written by hand, so nobody is on it who is not.

<Contributors />

## Commits are not the whole list

A commit count is what GitHub can measure, not what a project is made of.
It leaves out the person who reported the bug that took a day to find, the
one who read the quickstart and said which paragraph made no sense, and the
one who argued a design was wrong and turned out to be right.

If that was you and you want to be on this page, open a pull request that
adds you — that is the one honest way to get a commit.

## How to get on it

The roadmap is public and bigger than one person. Nothing here needs
permission first:

- **Build something and file what breaks.** The most useful thing anybody
  has done so far. Every one of the
  [open issues](https://github.com/MUKE-coder/flare-framework/issues) that
  came from real use was worth more than one written at a desk.
- **Pick a `good first issue`.** They are
  [tagged](https://github.com/MUKE-coder/flare-framework/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22),
  triaged, and each has enough written down to start without asking.
- **Take a roadmap item.** Multi-tenancy, field-level permissions, a plugin
  system — the large ones, each with a write-up.
- **Write.** A guide, an example app, one of the
  [projects](/projects/), or a page that explains the thing you had to work
  out yourself.

Flare is MIT, and a project becomes real the day it stops being one
person's.
